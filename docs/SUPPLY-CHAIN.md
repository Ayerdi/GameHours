# Supply-chain hardening

GameHours keeps supply-chain controls deliberately small and reviewable: reproducible NuGet restores, automated dependency update proposals, immutable GitHub Action references and least-privilege workflow tokens. Repository-hosted security features should use GitHub's low-maintenance defaults unless a concrete need justifies custom workflow code.

## Repository-side controls

### Reproducible NuGet graph

`Directory.Build.props` enables lock-file generation with:

```xml
<RestorePackagesWithLockFile>true</RestorePackagesWithLockFile>
```

Every solution project has a committed `packages.lock.json`. The lock files were generated by NuGet on the Windows CI runner with .NET SDK 8.0.424; they were not hand-authored.

Normal CI and the manual Windows packaging workflow restore the solution with:

```text
dotnet restore GameHours.sln --locked-mode
```

A dependency/version graph that no longer matches the committed lock files therefore fails restore instead of silently resolving a different graph.

The standalone `scripts/package-windows.ps1` path also restores the Desktop project for its actual publish RID before publishing:

```text
dotnet restore <Desktop.csproj> -r win-x64 --locked-mode
```

and then publishes with `--no-restore`. This avoids a hidden second dependency resolution during packaging while still producing RID-specific assets.

### Dependabot version updates

`.github/dependabot.yml` schedules independent weekly update proposals for:

- NuGet dependencies;
- GitHub Actions.

The update streams are intentionally not grouped into one large dependency PR. Each ecosystem is capped at five open update PRs so dependency maintenance stays reviewable.

### GitHub Actions

The existing workflows already used full commit SHAs before this hardening. Current external actions remain pinned to full immutable SHAs, including checkout, setup-dotnet and upload-artifact where used.

Workflows explicitly use:

```yaml
permissions:
  contents: read
```

and checkout uses `persist-credentials: false`.

No broader token permissions were added for supply-chain work.

## GitHub-hosted security settings

The repository is public and already protects `main` with an active ruleset requiring a pull request, unresolved-thread resolution, squash-only merging, non-fast-forward/deletion protection and the Windows CI status check.

Some security controls are repository settings rather than source files. The GitHub connector available during implementation can read repository/ruleset state but cannot change these settings, so their state must be verified/enabled from the GitHub UI before this roadmap item is called fully complete.

Recommended settings:

1. **CodeQL analysis — Default setup.** GitHub recommends default setup as the lowest-maintenance starting point for eligible repositories. GameHours does not need an extra hand-maintained CodeQL workflow unless default setup later proves insufficient.
2. **Dependabot alerts / security updates.** Confirm they are enabled under Advanced Security. Version updates from `dependabot.yml` are a separate repository-side control.
3. **Secret scanning + push protection.** Confirm Secret Protection is enabled for the public repository and push protection is active.
4. **Require Actions pinned to a full-length commit SHA.** The workflow files already comply; enabling the repository policy prevents future regressions.

Do not claim these settings are active merely because the repository files are ready for them.

## Change discipline

When Dependabot proposes an update:

- review the dependency/action release and security context;
- let the lock-file diff show the transitive graph change;
- require the normal Windows CI gate;
- do not regenerate lock files with unrelated dependency changes mixed into the same PR;
- keep Action references on full-length SHAs even when Dependabot updates the human-readable version comment.
